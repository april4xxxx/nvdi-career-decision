# 开发约定

> 面向接下来的高频改动（文案调整 + 新增功能模块）。目标：改得快、不踩坑、不引入构建成本。
> 原则：**能跑 > 优雅。** 黑客松窗口内不做全局重构，只在反复卡壳的单点做外科手术式拆分。

---

## 一、架构速览

- **无构建、无打包、无框架。** 纯 vanilla JS，classic `<script>` 标签直接加载。
- 这样做是**刻意的**：为了 `file://` 直接打开也能跑（免 CORS）。不要引入 ES modules / import / 打包工具，否则会破坏这一点。
- 所有模块都是 IIFE，挂到全局命名空间 `window.App` 上：

  ```js
  (function () {
    "use strict";
    window.App = window.App || {};
    // ...模块实现...
    window.App.xxx = { init: init, /* 对外方法 */ };
  })();
  ```

- 前端是静态资源，后端是 Vercel serverless（`api/chat.js`）。浏览器只请求同源 `/api`，**API Key 永不进浏览器**（见 `js/api.js`）。

---

## 二、加载顺序（改 `index.html` 时的铁律）

`index.html` 底部的 script 顺序**就是依赖顺序**，后面的模块可以用前面挂好的 `window.App.*`。当前顺序：

```
economy.js          ← 纯计算，无依赖
data.js             ← 所有静态数据 / 文案 / mock brain（最先，大家都依赖它）
store.js            ← 全局状态 + 事件总线 + 成就引擎（依赖 data）
api.js              ← 浏览器端服务适配器
onboarding / panel / topbar / scene / conversation-rules / conversation /
drawer / modes / library / treasury / demo   ← 各功能模块（依赖 data + store）
main.js             ← 最后：装配所有模块、绑定全局事件、启动引导
```

**新增模块的 script 标签，必须放在 `data.js`、`store.js` 之后、`main.js` 之前。** 放错位置会因为 `window.App.store` 还没挂上而报 undefined —— 这是无打包环境里最容易反复浪费时间的坑。

---

## 三、新增一个功能模块（三步模板）

**1. 新建 `js/xxx.js`：**

```js
/* =============================================================
   xxx.js —— 一句话说明这个模块干什么
   ============================================================= */
(function () {
  "use strict";
  var App = window.App;
  var store = App.store, ui = App.ui;

  function init() {
    // 绑定 DOM 事件、订阅 store 变化、首次渲染
  }

  window.App.xxx = { init: init };
})();
```

**2. 在 `index.html` 里加 script 标签**（位置见上一节规则）：

```html
<script src="js/xxx.js"></script>
```

**3. 在 `main.js` 的 `initApp()` 里加一行初始化：**

```js
App.xxx.init();
```

> `initApp()` 只在进入 app 主屏幕后执行一次（`appInited` 守卫）。Onboarding 阶段不会触发。

## 四、可复用的公共设施

改动前先看有没有现成的，别重复造：

### store（`js/store.js`）—— 全局状态 + 事件总线

- `store.get()` 读当前状态快照。
- `store.on(事件名, 回调)` 订阅。现有事件至少包括：
  - `"achievement"` —— 成就解锁，`main.js` 已全局接管弹通知。
  - `"enterApp"` —— 进入主屏幕，触发 `initApp()`。
- 新模块要响应状态变化时，**优先订阅 store 事件**，不要自己轮询。

### ui（`window.App.ui`）—— DOM / 弹层助手

- `ui.$(选择器)` 取元素。
- `ui.closeModal()` / `ui.$("#overlay")` 弹层控制。
- `ui.achToast(def)` 成就轻量通知。
- ESC 关闭弹层/抽屉/面板、点遮罩关闭，已在 `main.js` 全局绑定，新模块无需重复处理。

### api（`js/api.js`）

- `App.api.chat(payload)` 调 `/api/chat`（超时 45s）。
- `App.api.uploadKnowledge(file, title)` 上传典籍。
- 错误文案已内置（超时 `大臣思虑过久，请稍后再试` 等），直接 catch 用即可。

## 五、改文案（最高频）

- **绝大多数用户可见文案集中在 `js/data.js`** 的对象字面量里：`EMPRESS_TYPES` / `QUIZ` / `SCENES` / `MINISTERS` / `SCENARIOS` / `ACHIEVEMENTS` / `MYSTIC_CARDS` 等。
- 改文案 = 改数据，不碰逻辑。**别把集中的文案打散回各个模块里**。
- 完整文案索引见 `prd-模块拆分/` 各模块的 `### 文案` 板块。

---

## 六、缓存刷新（`?v=` 参数）

- 部分 script 带查询串，例如 `data.js?v=onboarding-main-example-20260721`。
- 这是**破缓存戳**：改了某个 JS 后，如果线上/浏览器可能缓存旧版，就更新它的 `?v=` 值（惯例：`简述-日期`）。
- 边缘缓存会让"已改的东西看起来没生效"，排查白改问题时先确认这个戳有没有更新。

---

## 七、不做的事（守住时间盒）

- ❌ 不引入构建工具 / 打包 / ES modules / 前端框架。
- ❌ 不做全局重构。`store.js` 虽大（~1400 行），**仅当改动反复卡在它内部时**才局部拆分（成就引擎 / 任务投放 / 持久化各自独立），且只拆这一处。
- ❌ 不动 `api.js` 里"Key 不进浏览器"的边界。
- ✅ 加东西优先"新开文件 + 挂 `window.App`"，保持牵一发不动全身。
